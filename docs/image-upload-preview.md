# 图片压缩与 Bucket 上传实验

本地地址：`http://192.168.1.176:3003/image-upload-preview`。无需用户登录，与首页、Tally、账号系统独立，生产模式下页面和上传接口均关闭。

## 对比能力

| 版本 | 编码质量参数 | 默认长边上限 |
| --- | --- | --- |
| 原图 | 不重新编码，保持原始字节 | 不变 |
| 高清 | 0.90 | 3200 px |
| 均衡 | 0.75 | 1920 px |
| 省流量 | 0.50 | 1280 px |

- 输出格式可选 WebP 或 JPEG；关闭“同时限制长边尺寸”可在相同分辨率下只比较编码质量。
- 按比例缩放，不放大小图。显示实际格式、尺寸、大小、相对原图体积变化、解码与编码耗时、上传加签名耗时。
- 选择图片仅本地解码/压缩，不自动上传。支持单档上传、全部待上传档位顺序上传、下载本地版本、打开大图、切换本地/云端预览。
- 使用浏览器原生 `Canvas.toBlob`，无服务端图片压缩或 Next Image 优化。压缩结果有时可能更大，页面如实显示“增大”。质量参数不是画质保留百分比。
- JPEG 透明区域填白，WebP 保留透明。压缩版本重新编码，可能丢失 EXIF/色彩元数据；原始上传不改变原始文件。只测试静态 JPEG/PNG/WebP，不保留动画，不支持 SVG/GIF/HEIC。
- 输入限制 20 MiB、4000 万像素、单边 12000 px，避免无限制内存消耗；浏览器仍需先解码才能得知尺寸，大图对低内存手机存在压力。版本生成顺序执行，切换图片/离开页面释放 Blob URL 和 Canvas。

## Supabase 变更与边界

只创建了专用私有 bucket `image-compression-lab`，允许 JPEG/PNG/WebP，单文件最大 20 MiB。没有新增业务表、修改认证配置、开放匿名写入策略或改动现有 bucket。

根据 Supabase skill 的密钥隔离要求，浏览器将已经处理好的二进制文件发到 `/image-upload-preview/upload`，本地后端转存到固定 bucket；服务端密钥不发送给浏览器。不要求用户登录不等于给整个 Storage 开放匿名写权限。

后端原样存储，不重新编码；路径使用随机 UUID，不接受客户端指定 bucket 或路径，不覆盖原有文件。上传成功后生成一小时有效的签名预览 URL，界面切换为实际云端图片。签名 URL 是临时访问凭证，不记录到测试报告中。

上传接口仅允许开发环境及固定 Origin（沿用 `AUTH_PREVIEW_ORIGIN`，默认上述 3003 局域网地址），验证 MIME/文件签名和流式字节上限，进程内限制最多 2 个并发、30 次请求/分钟。这是可信局域网实验入口，不是生产级匿名上传或完整恶意文件扫描；客户端伪造 Origin 无法作为互联网防护。正式开放需另做身份、配额、分布式限流和更完整的文件验证。

没有文件 TTL、自动清理或云端文件列表。刷新/重新选择仅清空本页结果，不删除云端文件。测试文件暂时保留，可在专用 bucket 中查看；删除需通过 Storage API 或控制台，不直接删除 `storage.objects` 记录。签名生成失败时只尝试回滚刚上传的那个对象。

此实验采用普通上传，不含断点续传。官方建议超过 6 MB 的生产上传使用 TUS；当前 20 MB 是实验上限，不是生产部署承诺。上传耗时包含浏览器到本地服务、服务到 Supabase 以及生成签名的全链路时间，不能当作纯网络传输基准。

## 设置与测试

已有 `.env` 的服务端 `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY` 即可。专用 bucket 已创建；需要复建时显式运行下列脚本，已有 bucket 配置不一致会拒绝覆盖：

```sh
node --env-file=.env --import tsx scripts/setup-image-lab.ts
node --import tsx --test tests/image-lab.test.ts
npx tsc --noEmit
```

浏览器脚本默认不写云端。需使用已安装的 Playwright，若不在项目依赖中可指定 `PLAYWRIGHT_MODULE` 为安装目录：

```sh
# 只测试前端；使用项目里的 PNG 图
node tests/image-lab.browser.cjs

# 明确允许真实上传；可额外指定一张本地 JPEG 照片
IMAGE_LAB_LIVE_UPLOAD=1 IMAGE_LAB_PHOTO=/absolute/path/photo.jpg node tests/image-lab.browser.cjs
```

脚本不会启动服务、创建账号或修改业务数据。它测试原图 SHA-256 不变、编码格式与分辨率、透明度、无自动上传、无效/超大文件、响应式布局；启用真实上传时，还会从 Supabase 下载各版本核对 SHA-256，并验证无签名的公开地址不能读取这些私有对象。报告和截图写入独立 `/tmp/image-lab-results-*`，不包含签名 URL 或密钥。运行真实上传测试会产生文件和少量 Storage 流量，并保留这些测试对象。

## 已完成的真实测试（2026-09-08）

使用本机无头 Chromium 151.0.7922.34，在现有 3003 服务测试；没有启动新服务。下列 MB/KB 按 1024 换算，与页面显示一致。耗时为本次环境的单次测量，不代表手机、所有浏览器或所有图片的表现，也没有自动评定视觉质量。

约 2000 万像素的 JPEG 照片，原始 3648 × 5472、2,530,569 字节（2.41 MB），WebP 加尺寸限制的结果：

| 版本 | 分辨率 | 文件大小 | 体积减少 | 缩放及编码耗时 |
| --- | --- | --- | --- | --- |
| 原图 | 3648 × 5472 | 2.41 MB | — | 无需编码 |
| 高清 | 2133 × 3200 | 1.15 MB | 52.48% | 3292 ms |
| 均衡 | 1280 × 1920 | 212.5 KB | 91.40% | 1110 ms |
| 省流量 | 853 × 1280 | 55.3 KB | 97.76% | 459 ms |

同一照片关闭尺寸限制，维持 JPEG 输出及原始 3648 × 5472 分辨率：

| 版本 | 文件大小 | 体积减少 | 编码耗时 |
| --- | --- | --- | --- |
| 高清 / 0.90 | 2.20 MB | 8.81% | 1624 ms |
| 均衡 / 0.75 | 1.66 MB | 31.02% | 773 ms |
| 省流量 / 0.50 | 1.32 MB | 45.51% | 609 ms |

另测项目内 1672 × 941 PNG 示意图（1,150,947 字节）：WebP 高清 121,754 字节，均衡 76,180 字节，省流量 43,046 字节。前两档不缩小分辨率，第三档缩至 1280 × 720。

结论：浏览器可以完成这一实验需要的压缩；本次照片的显著降幅来自输出格式、尺寸和质量参数共同变化，不能把 91.4% 都归因于降低编码质量。图片内容和输入文件本身的压缩程度也会影响结果。

测试验证：

- 三组 × 四档共 12 个版本真实上传，逐个下载并核对 SHA-256；原图与输入文件字节一致，云端与浏览器生成的文件字节一致。
- 12 个私有对象均无法通过无签名的公开地址读取，签名预览可正常加载。
- WebP 透明度保留、JPEG 透明区域填白、小图不放大、选择文件不自动上传、错误文件及超限文件拦截、跨 Origin 拒绝通过；320/375/768/1440 宽度无横向溢出，浏览器未发生页面脚本错误。
- TypeScript 检查、相关文件 ESLint、40 项单元/回归测试、`git diff --check` 通过。
- 这轮完整测试及调试阶段共保留 18 个对象，16,026,639 字节（约 15.28 MiB）。仅在专用实验 bucket 内，没有删除其他文件；这些对象不会自动过期删除。
