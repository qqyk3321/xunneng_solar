# 员工内部查询项目：Tally 咨询与匿名留言

日期：2026-09-18

状态：规划，尚未实施。范围是独立项目 `ticket-query-local`，每个列表固定每页 10 条，只读展示主站已保存的数据。

## 数据依据与边界

- Tally：`public.tally_form_submissions`。仓库 V2 migration 定义姓名、邮箱、电话、国家、地址 JSON、提交时间、接收时间和原始 `payload`。
- 匿名留言：`public.anonymous_inquiries_preview`。包含邮箱、国家、时间、纯文本 `message`、富文本 `content`、`format` 和 `images`。
- 匿名留言图片：现有私有 bucket `anonymous-inquiry-images-preview`。
- 当前内部项目和主站部分历史代码仍使用旧 `location_json`、`response_id` 等字段；不能直接拿旧读取代码作为新表字段依据。
- 本规划只核对了仓库代码与 migration。实施前只读确认内部项目连接的项目与主站一致、实际列与 V2 一致；不读取或展示凭据值。
- 不新增或修改表、列、索引、RLS、Storage policy、Webhook 或 Edge Function，不同步复制客户记录。
- 本期不包含编辑、删除、回复、处理状态、分配员工、导出或发送邮件。

## 导航与页面

| 路径 | 用途 |
| --- | --- |
| `/` | 默认进入 `/submissions` |
| `/submissions` | Tally 咨询列表 |
| `/submissions/[id]` | Tally 咨询详情，保留已有详情路径 |
| `/inquiries` | 匿名留言列表 |
| `/inquiries/[id]` | 匿名留言详情 |
| `/solar-analysis` | 保留现有光伏分析入口 |

共两个业务查询入口，每个有独立详情页。使用中文员工界面，客户原始问题和内容保留原语言。采用紧凑表格、顶部筛选栏及统一导航，不额外建设统计首页。

## Tally 咨询

### 列表

列：工单编号、姓名、邮箱、电话、安装国家、提交时间、查看详情。

筛选：国家（全部/AG/DM）、邮箱（完整匹配/包含匹配）、关键词（姓名/电话/提交编号）、提交日期。邮箱、日期及排序遵循下方两个页面共用的协议。主编号按精确值查询，不能误把行号当成提交编号。筛选输入按字段类型处理，关键词中特殊字符不能改变查询语法。

### 详情

- 联系资料：姓名、邮箱、电话、国家；邮箱/电话提供复制操作。
- 安装地址：Parish、Town / Village、Street / Area、House / Building、Landmark / Directions。空选填项显示“未填写”，Directions 保留换行。
- 表单回答：按保存的 `payload.data.fields` 顺序展示，保留原题目编号，不套用最新表单标题。已在联系资料/地址展示的字段可通过经过确认的字段 key 避免重复，未知字段保留。
- 单选、多选：利用事件内 `options` 将答案 ID 对应到可读文字，保留 Other 的实际内容。无法解析时显示已保存的原始值，不猜答案。
- 电器矩阵：利用 rows/columns 映射成“电器 / 数量”表格。
- 多文件：按所属题目分组，显示文件名、可用的类型/大小；图片按需预览，视频不自动播放，PDF 等提供打开链接。使用数据库事件已有地址，不主动同步下载附件。
- 元数据：form ID、submission ID、提交时间、接收时间放在次要位置。
- 仅在事件保存了可用的预览/PDF 地址时提供链接，不要求旧版独立 URL 列存在，不调用 Tally 获取新内容。
- 失效附件单独提示，正文继续可读；未知类型提供局部原始值展开。

## 匿名留言

### 列表

列：留言编号（可缩写）、邮箱、国家、留言摘要、提交时间、查看详情。

筛选：国家（全部/AG/DM/未记录）、邮箱（完整匹配/包含匹配）、关键词（留言正文）、提交日期。邮箱、日期及排序遵循下方共用协议。历史国家为空时显示“未记录”，不推断。

摘要使用已存 `message`，显示约 80 个字符；只读取本页 10 条的必要字段，不取富文本正文和图片二进制。若需读取完整 message 后截断，范围也仅限本页。

### 详情

- 显示完整编号、邮箱、国家与提交时间。
- 纯文本转义显示并保留换行。
- 富文本按允许的节点渲染段落、标题、列表、强调及图片位置，不直接执行保存的 HTML。
- 复用主站已验证的富文本解析及附件路径校验规则，在独立项目内整理需要的模块，不跨项目引用主站运行时或开发专用路由。
- 私有图片仅在打开详情时由服务器生成临时访问链接，沿用一小时有效期和记录路径绑定校验；链接过期可刷新。
- 历史 format 为空的数据兼容显示；富文本异常可回退到 message，图片异常不阻断文字阅读。

## 两个页面共用的筛选与排序

### 日期过滤

- 提供开始日期、结束日期两个日期选择框，可选择同一天，也可以只填一端；两端都空表示全部日期。
- 快捷范围：全部、今天、昨天、近 7 天、近 30 天、自定义。近 N 天包含今天以及之前 N-1 个自然日，不使用滚动 N×24 小时定义。
- 日期筛选、快捷范围和页面时间均采用 `Asia/Shanghai`（北京时间 UTC+8），筛选区域明确标注。客户端所在时区不改变筛选结果。
- Tally 按 `submitted_at` 过滤和排序；匿名留言按 `created_at` 过滤和排序。Tally 的 `received_at` 只在详情作为接收时间展示，避免延迟推送改变客户提交日期。
- 开始日期包含当天 00:00；结束日期包含当天全天。服务器转换为 UTC 查询边界，使用“>= 开始日 00:00，< 结束日次日 00:00”，不拼接 23:59:59 造成毫秒记录遗漏。
- 例如选择 2026-09-01 至 2026-09-18，实际 UTC 范围是 `>= 2026-08-31T16:00:00Z` 且 `< 2026-09-18T16:00:00Z`。
- 开始日期晚于结束日期或日期无效时就地提示，不发送含错误条件的查询，也不偷偷退回无筛选结果。
- 快捷范围应用时转成明确的起止日期保存在 URL；分页使用同一范围，跨过午夜不会改变当前查询。重新选择快捷范围时才按当天计算。

### 邮箱过滤

- 一个邮箱搜索框，旁边提供匹配方式：默认“完整匹配”，可改为“包含匹配”。
- 完整匹配：例如 `customer@example.com`，只查这个邮箱的提交；去掉输入首尾空格，匹配不区分大小写。
- 包含匹配：例如 `customer` 或 `@example.com`，查包含该文字的邮箱。允许部分地址，输入控件不能以完整邮箱格式校验阻止查询。
- 空输入表示不限制邮箱；保存和展示仍使用数据库中的原始邮箱，不改记录。
- 邮箱输入中的 `%`、`_`、`*`、逗号等按字面内容处理，不允许变成通配符或额外查询条件。实施时验证数据库过滤接口的正确转义。
- 两种匹配方式用于查找联系信息，不用于确认账号身份或记录归属。

### 排序

| 排序项 | 展示含义 | Tally 字段 | 留言字段 |
| --- | --- | --- | --- |
| 提交时间：最新优先（默认） | 时间倒序 | submitted_at DESC | created_at DESC |
| 提交时间：最早优先 | 时间正序 | submitted_at ASC | created_at ASC |
| 邮箱：A–Z | 邮箱升序 | email ASC | email ASC |
| 邮箱：Z–A | 邮箱降序 | email DESC | email DESC |

- 顶部排序下拉框与表头时间/邮箱排序按钮操作同一份状态，表头显示当前排序方向。
- 时间相同时按唯一 ID 排序；邮箱相同时再按提交时间倒序、唯一 ID 排序，保证数据不变时跨页顺序一致。
- 邮箱排序沿用数据库既有文本排序规则，不承诺大小写归一化后的排序，不为此新建索引、视图或数据库函数。
- 排序作用于符合筛选条件的全部记录，再截取当前页，不能仅对本页 10 条在浏览器中重排。

### 条件组合与交互

- 日期、邮箱、国家、关键词之间用 AND 组合，必须同时满足。Tally 关键词内部可匹配姓名、电话或提交编号中的任意一个。
- 日期/邮箱/国家/关键词编辑后，点击“查询”或按 Enter 一次性应用，回到第一页，避免每输入一个字符就查数据库。
- 切换排序立即生效并回到第一页，使用已应用的筛选条件；尚未提交的筛选输入保留为草稿，不悄悄参与排序查询。
- “重置”清空筛选，恢复最新优先及第一页。“刷新”重新读取当前已应用的条件、排序及页码。
- 列表显示已应用的日期范围、邮箱匹配方式和筛选后总数，让员工明确正在查看什么。
- URL 保存已应用状态：`from`、`to`、`email`、`emailMode=exact|contains`、`country`、`q`、`sort=time|email`、`direction=asc|desc`、`page`。
- 两个页面独立保存于各自 URL，不默认把一个页面的条件带到另一个页面。刷新、浏览器前进/后退、详情返回和复制链接都能还原对应查询。

## 分页与状态

- 两页固定 10 条，不提供每页条数切换。
- 数据库分页，统计与列表使用完全相同的过滤条件，按上方排序协议执行，默认时间倒序。
- 显示总数、当前范围、页码和上一页/下一页，支持指定页跳转。
- 筛选变化回到第一页；分页保留筛选，详情返回原列表时保留查询参数。
- 非法页码归一为第一页，超范围页码归一为最后有效页；并发新增时列表允许在刷新后变化。
- 区分首次加载、没有任何数据、筛选无结果、查询失败、记录不存在和附件不可用。
- 日期显示明确标注时区；初版沿用内部项目的北京时间（UTC+8），可见原始客户内容保持不变。

## 读取与部署约束

- 内部 Next.js 服务器直接查询主站正在使用的云端项目，浏览器不持有 Supabase secret/service-role key。
- 密钥只配置在内部项目自己的服务端环境变量中；页面及读取响应不进入共享缓存。
- 应用仅提供查询行为；现有服务器密钥不因此变成数据库级只读凭据，不声称权限已收紧。
- 使用现有员工内网部署边界，本期不建设账号系统；公网部署前需另行明确员工访问限制。
- 数据库查询失败显示可重试提示，不把底层错误或凭据输出到页面。

- 数据读取失败不显示成“0 条”，不把空结果误判为查询故障。
